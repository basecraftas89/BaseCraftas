## 動的な仕掛けについて（2026-08 追加）

### 次回開催までのカウントダウン
「毎週土曜6:00」という規則から**自動計算**しています。日付データを書き換える必要はありません。
開催中（土6:00〜6:30）は自動で「いま開催中です」に切り替わります。
表示したい場所に `<div class="countdown" data-countdown></div>` を置くだけで増やせます。

### 申込リンクの一元管理
`data-apply="ラベル"` が付いたリンクには、`config.js` の `APPLY_URL` が自動で入り、
`?from=ラベル` が付きます。**セラピストドットコム側で「どこ経由の申込か」を見分けられます。**

### モバイル下部の固定CTA
860px以下でのみ表示。ヒーローを過ぎたら出て、最終CTAに近づくと引っ込みます。

### 週間サイクルの「今日ここ」
`index.html` のタイムライン `<li>` に付けた `data-days="2"`（0=日〜6=土）を見て、
訪問した曜日のステップに「今ここ」バッジが付きます。

### 画像の読み込み（重要）
トップページの画像は合計10MBあります。ファイルは軽量化していませんが、
**ファーストビュー以外の画像に `loading="lazy"` を付けて後回しにしている**ため、
最初に読み込むのは1.7MBだけです。

- ヒーロー画像（`hero-main.jpg` / `seminars-hero-flow-v2.jpg`）… `fetchpriority="high"` で先に読む
- それ以外 … `loading="lazy"` でスクロールして近づいてから読む
- 全画像に `width`/`height` を入れて、読み込み中のガタつきを防いでいます

**画像を差し替えるときは、`width`/`height` も実際の縦横に直してください。**
数値がズレると表示が歪みます。

なお、根本的にはPNGをWebPに変換すると同じ見た目のまま10MB→0.5MBになります
（実測で-95%）。将来やる場合はここを検討してください。

### CSS・JSを変更したときの必須作業（重要）

各HTMLの読み込みには、バージョン番号が付いています。

```html
<link rel="stylesheet" href="styles.css?v=20260808">
<script src="common.js?v=20260808"></script>
```

**`styles.css` や `*.js` を変更したら、全HTMLの `?v=` の数字を必ず新しい日付に変えてください。**

これを忘れると、訪問者のブラウザが**古いCSSをキャッシュから使い続けます**。
新しいHTMLと古いCSSが組み合わさると、レイアウトが崩れます（実際に一度発生しました）。

一括で置き換える場合は、エディタの「フォルダ内検索・置換」で
`?v=20260808` → `?v=（今日の日付）` とすれば全ファイル一度に直せます。

なお、自分で確認するときは **Macなら Cmd+Shift+R、Windowsなら Ctrl+Shift+R**
でスーパーリロードすると、キャッシュを無視して読み込み直せます。

### アニメーションの方針
端末に負荷がかかる**常時ループするアニメーションは置いていません**。
動くのは「意味のあるときだけ」に限定しています。

| 動くもの | いつ動くか |
|---|---|
| カウントダウン | 常時（秒だけ・数字の差し替えのみ） |
| 「今ここ」のポップ | 画面に入ったとき1回だけ |
| 固定CTA | 出入りするとき |
| FAQ | 開いたとき |
| 参加者の声 | 6.5秒ごとに切替 |
| 開催中の点滅 | 土曜6:00〜6:30の30分間だけ |

**「動きを減らす」設定にしている人には、すべての演出が自動で止まります。**

## 参加者の声・アンケート集計（voices.js）

トップページの「VOICES」セクションで使っています。データの出どころは2段構えです。

1. `config.js` の `SURVEY_CSV_URL` に公開CSVのURLが入っていれば、そちらを読む
2. 未設定・読み込み失敗のときは `voices.js` の `FALLBACK` を表示

**つまりURLを設定しなくてもサイトは正常に動きます。** 設定した瞬間から自動更新に切り替わります。

### 集計シートの作り方

Googleスプレッドシートに **集計専用のタブ**を1つ作り、次の5列で並べます。
（アンケート原本のタブには氏名・メールアドレスが入っているため、**原本をそのまま公開しないでください**）

| A列 type | B列 | C列 | D列 | E列 |
|---|---|---|---|---|
| `stat` | `satisfaction` | `8.2` | | |
| `stat` | `responses` | `92` | | |
| `stat` | `nagara` | `34.8` | | |
| `stat` | `sessions` | `11` | | |
| `voice` | 回答本文 | `40代・男性` | `画面に集中して参加` | `10` |
| `voice` | 回答本文 | `40代・女性` | `移動しながら参加` | `8` |

- `stat` の行はB列がキー、C列が数値。キーは `satisfaction` / `responses` / `nagara` / `sessions` の4つ
- `voice` の行はB列が本文、C列が属性、D列が参加スタイル、E列が満足度
- B列・C列は `=QUERY(...)` や `=FILTER(...)` で原本タブから引いてくると、更新の手間がなくなります

そのうえで **「ファイル → 共有 → ウェブに公開」→ 集計タブを選び → 「カンマ区切り形式(.csv)」** で公開し、
発行されたURLを `config.js` の `SURVEY_CSV_URL` に貼ります。

### 掲載のルール（守ってください）

- **氏名・メールアドレス・所属は絶対に載せない**（原本タブには入っています）
- 回答本文に個人名が出てくる場合は、その一文を削るか伏せ字にする
- **運営メンバー自身の回答を「参加者の声」として載せない**（景表法・ステマ規制の対象になり得ます）
  アンケート原本の `運営判定` 列で切り分けられます
- アンケートに「サイトへの掲載可否」を聞く設問を追加しておくと、より安全です

## コンテンツページ（contents.html）の中身

「Podcast」「学習コンテンツ」「アーカイブ動画」の**タブ切替**になっています（アンカーでのスクロールではなく、
クリックでその場のパネルが入れ替わる方式）。タブの切替は `tabs.js` が担当し、
中身の描画（stand.fm埋め込み・資料カード・アーカイブ一覧）は `contents.js` が担当します。

- **Podcastタブ（`#podcast`）** … stand.fmのPodcastバックナンバー。新しい順／古い順の並び替え、
  「回で絞る」（10回ごとのまとまり）、横スライドの一覧、視聴済み管理
- **学習コンテンツタブ（`#library`）** … Googleドライブ／YouTubeに置いた学習資料の一覧（タグ絞り込み）＋資料の使い方
- **アーカイブ動画タブ（`#archive`）** … コメキャリメンバー限定の録画一覧（詳細は下の章）

他ページから `contents.html#podcast` や `contents.html#library` のようにリンクすると、
そのタブが最初から開いた状態で表示されます（`benefits.html` や `faq.html` からのリンクはこの仕組みを使っています）。

学習コンテンツの資料が0件のときは「Podcastを聴く」ボタンが出て、押すとPodcastタブに切り替わります。

### Podcastを追加する

`contents.js` 冒頭の `EPISODES` に1行足します。

```js
{ url: 'https://stand.fm/episodes/エピソードID', no: 10, theme: '', date: '8/1' },
```

- 表示順は `POD_ORDER`（`'newest'` / `'oldest'`）で切替
- 「視聴済み」はブラウザのlocalStorageに保存（サーバー送信なし）
- 「回で絞る」の10回ごとのまとまり（第1〜10回、第11〜20回…）は自動計算なので、
  11回を超えても手作業は不要です（アーカイブ動画タブと同じ仕組み。詳しくは下の章）

### 横スライドの一覧（Podcast・アーカイブ動画 共通の仕組み）

どちらのタブも、一覧は横スクロールする帯（`.pod-list` / `.archive-track`）の中に
カードを並べる作りで、`contents.js` の `setupSlider()` が矢印ボタン・マウスホイール・
スワイプの動きをまとめて面倒を見ています。

編集する側が知っておくとよい点：

- **`html { scroll-behavior: smooth }` をこの一覧の要素に効かせないこと。**
  スクロール位置の吸着（`scroll-snap`）と smooth スクロールを同じ要素に効かせると、
  矢印ボタンがまったく反応しなくなる不具合が実機で確認されています。
  そのため `.pod-list` / `.archive-track` には CSS 側で `scroll-behavior: auto` を
  明示的に指定しています（styles.css 内にコメントあり）。
- 矢印クリック時のアニメーションは `requestAnimationFrame` ではなく `setInterval` で
  実装しています（タブが背面にあるとアニメーションが止まって固まる問題があったため）。
- 指でのスワイプは、一覧自体が横スクロール可能な要素なのでブラウザ標準の動きがそのまま使えます。
  JS側で特別なスワイプ処理は書いていません。
- 並び替え・絞り込みボタンのクリック登録は、ページ読み込み時に**1回だけ**行っています
  （`initPodcastRanges()` / `initArchiveRanges()`）。ボタンを押すたびに登録し直す作りにすると、
  クリックのたびに処理が二重・三重に走るようになるため、意図的にこの形にしています。

### 学習資料を追加する（PDF・スライドなど／サムネイルなし）

`contents.js` の `CONTENTS` に1件追記します。資料の実体は**Googleドライブ**に置き、
サイト側にはリンクと説明だけを持ちます。

```js
{
  title:    '生成AIリテラシー入門 振り返り資料',
  desc:     '権限管理とデータ保存先の考え方を、出典リンク付きで整理した資料です。',
  tags:     ['現場での運用'],                     // 好きなタグを書くだけ（複数可・登録不要）
  date:     '2026-08-10',                        // 公開日。新しい順に自動で並ぶ
  type:     'PDF',                               // スライド / PDF / シート など
  url:      'https://drive.google.com/file/d/xxxx/view',
  source:   '2026/8/10 セミナー'                  // 任意。どの回の資料か
}
```

PDF・スライドなどのカードには、タグが小さなラベルとして表示されます。

### 動画を追加する（YouTube運用・サムネイル付きカード表示）

動画は **YouTube** で管理します（2026-07-29よりGoogleドライブ運用から切替）。
`youtubeId` を持つエントリにすると、YouTubeのサムネイル画像を使ったカードになり、
タップするとその場でポップアップ再生されます（セミナーページの詳細ポップアップと同じ構造）。

```js
{
  title:     '動画のタイトル',
  desc:      '概要（2文程度。カード面にそのまま表示されるので短くまとめる）',
  tags:      ['AIリテラシー'],
  date:      '2026-08-10',
  type:      '動画',
  youtubeId: 'YouTube動画のID（例: 8ubAUePSwY8）',
  source:    '出典・回のメモなど（任意）'
}
```

動画ID は `https://youtu.be/【ここがID】` または `https://www.youtube.com/watch?v=【ここがID】` の
IDの部分です。アップロード・サムネイル設定はYouTube Studioで行います。
チャンネルダッシュボード：https://studio.youtube.com/channel/UCBaZSkwcG8jsj8_gEaHrQ4w

**動画カードの面に表示されるのは「サムネイル・タイトル・概要（2文程度）・アップロード日」**です
（2026-08-15より、並び替えの基準が分かるようdateも表示するようにしました）。
タグ・出典はカードには表示されません（フィルター機能のために内部的には保持しています）。
概要（`desc`）は長文にせず、2文程度に収めてください。

### タグについて（設定不要・自由入力）

`tags: ['AIリテラシー']` のように、各エントリに好きなタグを書くだけで使えます。
どこか別の場所に一覧を登録する必要はありません。実際に使われているタグから、
学習コンテンツ上部のフィルターボタンが自動で作られます。1件に複数タグも付けられます
（例: `tags: ['AIリテラシー', '情報セキュリティ']`）。この場合その資料は両方のタグの
絞り込みに出てきます。

### アーカイブ動画タブ（コメキャリメンバー限定）

朝活の録画を、Googleドライブで限定共有した状態で並べているタブです。
サイト側は一覧・タイトルを出しているだけで、実際に見られるかどうかはGoogleドライブの
共有設定（Googleグループ）で決まります。設定手順は同梱の
「アーカイブ権限設定ガイド.md」を参照してください。

新しい回を追加するときは、`contents.js` の `ARCHIVES` の**先頭**に1件足します。

```js
{ no: 12, date: '2026-08-15', driveId: 'Googleドライブの共有IDだけを取り出したもの',
  title: '第12回のテーマ' },
```

「回で絞る」の10回ごとのまとまり（第1〜10回、第11〜20回…）は `no` の最大値から
自動計算しています。20回、30回と増えても手作業でボタンを増やす必要はありません。

### 「格納しました」で毎週自動更新する運用

Toshikiさんは毎回、朝活のあとに①stand.fmへ音源をアップロード、②Googleドライブの
アーカイブフォルダに録画動画を格納、という2つの作業を行います。次回以降、

> 「格納しました」（またはそれに類する一言）

とだけ伝えてもらえれば、以下を自動で行います。

1. **stand.fmチャンネル**（https://stand.fm/channels/605bc3ca2b49b926c82491cc ）を開き、
   最新エピソードのURL・タイトル（ラジオ側に入っているタイトルをそのまま使う）・配信日を取得
   → `EPISODES` の末尾に1件追加
2. **Googleドライブのアーカイブフォルダ**
   （https://drive.google.com/drive/folders/12YHtKFODi75v_W08xFACzm97DjFIUCjg ）を開き、
   最新の動画ファイル（`第N回 M/D.mp4`）のdriveIdを取得
   → タイトルは1で取得したPodcastのテーマをそのまま使い、`ARCHIVES` の**先頭**に1件追加
   （日付はPodcast側の配信日に合わせる。ファイル名の日付とズレる場合は確認する）
3. `contents.html` など全HTMLファイルの `?v=` キャッシュ用バージョンを更新
4. jsdomでの簡易検証（件数・並び順）
5. 接続済みの「ホームページ」フォルダへ同期

追加内容（タイトル・日付など）は都度チャットで簡単に報告します。内容に誤りがあれば
その場で修正できるようにしています。

## BGM再生ボタン（全ページ共通・ページを切り替えても鳴り続ける）

右下に浮かぶ「♪ 曲を再生」ボタンです。曲の実体は `assets/bgm-shumatsu.mp3`、
再生ロジックは `bgm.js` にまとめてあり、`sticky-cta` の直後に置いた
`<audio id="bgmAudio">` と `<button id="bgmToggle">` を持つ全7ページ
（index / seminars / benefits / join / contents / faq / privacy）で共通です。

- ブラウザは「ページを開いた瞬間に音を鳴らす」ことを許可していないため、
  **最初の1回だけ**ボタンを押してもらう必要があります。
- 一度押すと、再生中かどうかと再生位置（秒）を `localStorage` に保存します。
  次のページへ移動すると、その情報をもとに自動で同じ位置から再生を再開するので、
  体感としては鳴り続けているように見えます（完全に途切れないわけではなく、
  ページの読み込みごとに一瞬止まって再開する形です）。
- ブラウザ・環境によっては2ページ目以降も自動再生がブロックされることがあります。
  その場合はボタンの表示が「曲を再生」に戻るだけで、押せば保存済みの位置から続きが流れます。
- 曲を差し替えるときは `assets/` に新しいmp3を置いて、7ページ分の
  `<audio id="bgmAudio" src="...">` の `src` を書き換えてください。

## セミナーを追加・更新する（seminars.js）

`seminars.js` 冒頭の `SEMINARS` に1件追記します。

```js
{
  date: '2026-09-07',                    // 必須。YYYY-MM-DD
  dateLabel: '2026年9月7日（月）',
  time: '20:00〜21:00',
  title: 'セミナータイトル',
  subtitle: 'サブタイトル（なければ空文字）',
  speakerName: '講師名',
  speakerTitle: '所属・資格',
  price: '無料',
  thumb: 'assets/2026-09-07_theme-name.jpg',
  summary: 'カード・ポップアップに出る概要（1〜2文）',
  url: 'https://therapis10.com/seminars/xxxxx',
  tags: ['アーカイブ配信あり', '資料配布あり']
}
```

- 開催日を過ぎると自動で「開催終了」バッジになり、ボタンも「アーカイブを見る」に切り替わります
- サムネイルは `assets/YYYY-MM-DD_theme-name.jpg`。**16:9**で書き出し、200KB以下を目安に軽量化してください

## FAQを追加する（faq.html）

FAQも「参加について／内容について／セミナーについて／資料・コンテンツについて」の**タブ切替**です
（`tabs.js` を共用）。追加するときは、該当カテゴリの `.faq-list` 内に以下を追記するだけで、
タブの仕組みには手を加える必要はありません。

```html
<details class="faq-item">
  <summary>質問文</summary>
  <p>回答文。<a href="join.html">他ページへのリンク</a>も入れられます。</p>
</details>
```

カテゴリは 参加について / 内容について / セミナーについて / 資料・コンテンツについて の4つです。

## チャットボットについて（検討結果）

**導入は見送り。** GitHub Pagesは静的サイトのため、AIチャットボットを動かすにはAPIキーを
コード内に書く必要があり、公開ページから誰でも閲覧できてしまいます（キーの悪用・従量課金のリスク）。
回避するにはサーバーまたはクラウド関数の用意が別途必要です。

代替として「APIキー不要のFAQキーワード検索」も実装可能ですが、今回は見送りとしています。

## セキュリティの注意

- APIキー・アクセストークン・サービスアカウントJSON等の秘密情報は置かない
- 申込URLの招待コードは公開ページから誰でも見えます。限定運用したい場合は、後から無効化・差し替えできる招待リンクを使用してください
- Googleドライブの資料は「リンクを知っている全員が閲覧可」で公開されます。外部に見られて困る資料は載せないでください
- URL限定公開のstand.fmエピソードは「URLを知っていれば誰でも再生できる」状態です
